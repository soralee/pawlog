# 예방접종/검진의 "예정 일정"과 "완료 기록"은 같은 테이블의 같은 행으로 표현한다

`product-plan.md` §6·`screen-layout.md` §26이 "기록은 실제 일어난 일, 일정은 아직 안 한 일"이라는 원칙을 예방접종/검진에 명시적으로 적용하면서, Schedule에서 추가한 미완료 일정과 Records에서 추가한 완료 기록을 어떻게 데이터로 표현할지 결정이 필요했다. 대안으로 (a) `vaccinations`/`checkups`를 그대로 두고 실제 접종일/검진일 컬럼을 NOT NULL에서 nullable로 바꿔 null이면 "예정 일정", 값이 있으면 "완료 기록"으로 구분하는 방식과 (b) 일정 전용 테이블을 별도로 두고 완료 시 레코드를 새로 만드는 방식을 저울질했고, (a)를 택했다 — 테이블/마이그레이션이 하나 늘지 않고, "완료하기"가 같은 행을 UPDATE하는 것만으로 끝나 구현이 단순하며, Visibility Matrix(§6.7)가 "완료 여부로만 같은 행이 Records/Schedule 중 어디에 보일지 갈린다"는 모델과 정확히 맞아떨어진다. 대가는 "실제 접종일/검진일"이 더 이상 NOT NULL이 아니게 되어, 이 필드를 읽는 모든 코드가 null 가능성을 다뤄야 한다는 점이다. 아직 출시 전이라 기존 로컬 DB 데이터 보존 없이 마이그레이션 파일을 직접 수정했다(사용자 확인 완료) — 출시 이후였다면 정식 ALTER 마이그레이션이 필요했을 결정이다.
